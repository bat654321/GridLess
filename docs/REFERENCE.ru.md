# GridLess: справка о возможностях и алгоритмах

English version: [REFERENCE.md](REFERENCE.md).

Состояние на 23.11.2026 (версия 0.2.0). Справка описывает, что умеет
трассировщик, как он устроен внутри и какие параметры управляют каждым этапом.
Обзор аналогов и обоснование архитектуры — в [ANALYSIS.md](ANALYSIS.md), пример
настроек — в [example.gridless.toml](example.gridless.toml).

## 1. Что это

GridLess — бессеточный топологический автотрассировщик для KiCad 10 в духе TopoR.
Сначала строится *топология* (с какой стороны какого препятствия проходит каждый
проводник), затем точная геометрия «резиновой нити»: отрезки под любыми углами и дуги
вокруг площадок. Ядро написано на Rust; к KiCad подключается двумя плагинами или через
командную строку.

## 2. Возможности

### Трассировка
* Платы с любым числом слоёв; внутренние слои, почти целиком залитые зонами, считаются
  плоскостями (в том числе разделёнными между цепями).
* Ширины и зазоры — из классов цепей проекта KiCad; переопределяются по маскам имён.
* Автоматическое сужение проводника в узких местах до минимальной ширины правил.
* Дифференциальные пары (определяются по суффиксам `_P/_N`, `+/-`, `P/N` или задаются
  явно): одна полоса с постоянным зазором, парные переходные рядом, выбор
  эквивалентных выводов (USB-C A6/B6), компенсация перекоса.
* Выравнивание длин групп цепей меандрами-«тромбонами»; резерв места под меандры ещё на
  этапе топологии (`length_reserve`).
* Предпочтительные направления слоёв и «цена» слоя.
* Подключение площадок к полигонам и плоскостям: площадка, до которой дошла заливка
  своей цепи, остаётся заливке; остальным ставится переходное к плоскости.
* Сшивка островов полигонов после трассировки (`--stitch`, см. §4.9).
* Существующие трассы можно сохранить и развести только недостающее (`--keep-existing`).

### Качество результата
* Проводники огибают группы площадок, а не протискиваются между выводами
  («контурная карта», §4.4).
* Порядок разводки, как у конструктора: сначала узлы коротких связей, затем
  питание, затем остальное (§4.5).
* Выход из прямоугольных площадок под 90° к грани.
* Зазоры между соседними проводниками выравниваются, проводник между двумя
  площадками идёт посередине («радар», §4.7).
* Изломы скругляются дугами, вход в площадку — прямой (§4.8).
* Встроенная проверка правил и обратная связь «DRC → перекладка»; при наличии
  `kicad-cli` — проверка самим KiCad.

### Интерфейсы
* **Плагин IPC API (KiCad 10)**: трассирует открытую плату с несохранёнными правками и
  вставляет результат одним шагом отмены. Установка через PCM.
* **Классический ActionPlugin (SWIG)**: трассирует сохранённый файл.
* Оба плагина: диалог настроек, окно хода работы с журналом и кнопкой отмены,
  итоговый отчёт; интерфейс переведён на все 44 языка KiCad.
* **Командная строка** `gridless`:

| Команда | Назначение |
|---|---|
| `route BOARD -o OUT` | развести плату |
| `  -c FILE` | файл настроек (по умолчанию `<board>.gridless.toml`) |
| `  --project FILE` | проект `.kicad_pro` с классами цепей |
| `  --rounds N` | раундов «геометрия → DRC → перекладка» (8) |
| `  --keep-existing` | сохранить имеющиеся трассы |
| `  --kicad-check` | залить зоны через `kicad-cli`, добавить переходные к плоскости для площадок, которые заливка не достала, и развести заново |
| `  --stitch` | после трассировки сшить острова полигонов (как `stitch`) |
| `  --json-out FILE` | результат в JSON (для плагинов) |
| `  --png FILE --view x0,y0,x1,y1 --scale K` | картинка результата |
| `stitch BOARD -o OUT [--net GND]` | сшить острова полигонов на готовой плате |
| `render BOARD --png FILE` | нарисовать плату как есть |
| `  --view`, `--scale`, `--layers F.Cu,B.Cu` | окно, масштаб, слои (первый — сверху) |
| `  --no-fills` | без заливок |
| `  --nets A,B` | подсветить цепи, остальные приглушить |
| `  --markers "x,y;x,y"` | пронумерованные метки |
| `info BOARD [--json FILE]` | сводка о плате, модель в JSON |

## 4. Алгоритмы и методы

### 4.1. Модель платы и правила
Читатель `.kicad_pcb` разбирает S-выражения и помнит положение каждого узла в файле,
поэтому запись меняет только трассы и переходные, а остальной файл остаётся байт в
байт. Площадки любой формы представлены «скруглёнными выпуклыми многоугольниками»
(выпуклое ядро плюс радиус), что даёт точные расстояния для зазоров. Читаются контур
платы, зоны (в том числе вложенные в посадочные места: запреты Altium), запреты
по видам (дорожки, переходные, заливка), медные графические фигуры.

Правила (`Rules`) собираются из классов цепей проекта, правил платы и файла настроек.
Неметаллизированное отверстие моделируется кругом, увеличенным так, чтобы зазор
медь–отверстие (`hole_clearance`) выполнялся.

### 4.2. Задача трассировки
* **Препятствия** — площадки, сохранённые трассы, переходные, медь, запреты.
* **Места переходных** — гексагональная решётка с шагом «диаметр + зазор» плюс точки
  вокруг каждой SMD-площадки в 8 направлениях; места, нарушающие зазоры до
  препятствий, края платы или отверстий, отбрасываются.
* **Связи** — минимальное остовное дерево по площадкам каждой цепи. Ребро между
  площадками без общего сигнального слоя дороже на цену переходного (сквозные
  площадки и переходные меняют слой бесплатно). Длинное ребро, проходящее рядом с
  третьей площадкой цепи, разбивается на два через неё.
* **Выходы из мелкошаговых площадок** — короткий прямой отрезок вдоль длинной оси
  площадки, наружу от корпуса. Корпус считается мелкошаговым, если дорожка его цепи не
  помещается между соседними выводами (K1: площадки 0,31 мм с зазором 0,19 мм). Вывод,
  соединённый с выводом напротив в том же корпусе, выходит внутрь, под корпус.

### 4.3. Триангуляция
Для каждого слоя строится ограниченная триангуляция Делоне (crate `spade`). Вершины —
углы и центры препятствий, точки контура, места переходных, площадки. Стороны
препятствий и контура — ограничивающие рёбра. У каждого ребра хранится его «выход»:
расстояние, которое занимает препятствие на конце ребра вместе с зазором.

### 4.4. Контурная карта (terrain)
Медь чужих цепей — холм: полная высота 1 на самой меди и её полосе зазора, дальше
гауссов спад с параметром `terrain_sigma` (0,5 мм). Холмы складываются на сетке
0,1 мм, поэтому плотная группа выводов становится плато, а промежуток между группами —
долиной. Для проводника своя цепь — ровное место: её вклад вычитается при запросе.

Поиск пути платит за подъём: каждый шаг стоит `terrain × длина × средняя высота` в
дополнение к длине. Переходное платит `terrain_via × высота` в месте установки
(среднее по слоям). Следствия:
* проводник идёт между группами компонентов, а не между выводами одного корпуса;
* из ряда выводов проводник выходит поперёк ряда — так он быстрее спускается с плато;
* длинный участок идёт по свободному слою, переходное ставится у загруженного конца;
* переходные встают в долинах, а не среди площадок.

Отладочная картинка высот: переменная `GRIDLESS_TERRAIN_PNG=префикс`.

### 4.5. Порядок разводки (`order`)
`logic` (по умолчанию) повторяет порядок конструктора:
1. **Узлы.** Узел — группа коротких связей (до 6 мм), концы которых лежат в пределах
   1 мм друг от друга; в узле не меньше 3 связей, по размеру он не больше 8 мм. Узлы
   растут от самых коротких связей, поэтому собираются вокруг плотного ядра:
   реле с диодами, подтяжки разъёма, конденсаторы у микросхемы. Узлы разводятся
   первыми, самые плотные раньше, каждый целиком.
2. **Короткие связи в одном слое** (до `short_link`, 3 мм): хотя бы на одном конце SMD,
   есть общий слой — смена слоя здесь может только навредить.
3. **Питание** — цепи с повышенным приоритетом или шире ширины класса по умолчанию.
4. **Остальные** связи по длине; связи через сквозные площадки и переходные (смена
   слоя бесплатна) — здесь же.
5. **SMD–SMD на разных слоях** — последними: переходное им нужно в любом случае.

Дифференциальные пары всегда идут раньше всех. Прежние режимы: `width` (приоритет,
ширина, длина), `cost`, `short`, `auto` (развести тремя способами и выбрать лучший
по DRC KiCad).

### 4.6. Топологическая трассировка
Проводник хранится как последовательность пересекаемых рёбер триангуляции; на каждом
ребре пересечения разных проводников стоят в строгом порядке, поэтому эскиз каждого
слоя планарен по построению.

* **Поиск** — A* по состояниям «ребро + промежуток между уже проложенными
  проводниками». Переходы: через треугольник к противоположному ребру, к вершине
  (цель или место переходного), смена слоя через переходное.
* **Стоимость шага**: длина × множитель направления слоя; подъём по контурной карте;
  перегрузка ребра (не хватает места на всех) с растущим коэффициентом, как в
  PathFinder; накопленная история конфликтов ребра; штраф за сужение проводника;
  штраф за пересечение чужого проводника — цена его перекладки (rip-up); штраф за
  проход у площадки, к которой должна дойти заливка (`pour_keepout`); цена
  переходного (`via.cost`, 12 мм дорожки) плюс высота рельефа в его месте.
* **Переговоры (negotiated rip-up and reroute)**: связи разводятся по очереди;
  пересечённые проводники снимаются и ставятся в очередь снова. После прохода
  перегруженные рёбра получают историю, половина самых дешёвых для перекладки
  связей на них снимается, итерация повторяется (`iterations`, 40). Сохраняется
  лучшее состояние.
* **Минимизация переходных** (как «расслоение» TopoR): каждая связь с переходными
  пробуется без них при запретительной цене переходного; новый путь принимается, если
  не длиннее старого в 1,6 раза + 3 мм и не создаёт перегрузок.
* **Чистка**: каждая связь перекладывается в одиночку на устоявшейся плате;
  принимается более короткий путь или путь с меньшим числом переходных. Связь с
  большим обходом перекладывается вместе с 1–4 проводниками, которые ей мешают
  («кто кого обходит»).

### 4.7. Геометрия резиновой нити
Для каждого слоя (параллельно) строится новая триангуляция только по реальным
препятствиям, включая использованные переходные; проводники переносятся в неё.
Переменные — положения пересечений на рёбрах. Внутри треугольника проводник прямой
или огибает общую вершину дугой, радиус которой учитывает вложенные проводники
(концентрические пучки). Начальное положение — алгоритм «воронки» (funnel), затем
покоординатный спуск по длине с ограничениями зазоров вдоль каждого ребра.

* **Переходные сдвигаются** с узла решётки на прямую между концами, которые они
  соединяют (медиана для трёх и более), не дальше 1,2 мм, с соблюдением зазоров и
  без пересечения чужого проводника (иначе он обогнул бы новое место петлёй).
* **Сужение**: где места не хватает, ширина уменьшается до минимума правил.
* **Выравнивание зазоров («радар»)**: проводник между двумя площадками идёт
  посередине, пучок — с равными зазорами; каждый зазор не меньше своего правила.
  Влияние площадок ослабевает с расстоянием между ними: полное до `centering.full`
  (2 канала), нулевое от `centering.range` (5 каналов). Если выравнивание добавляет
  нарушения на слое, пробуется 50 % и 25 % силы.

### 4.8. Проверка, обратная связь, доводка
* **Внутренний DRC**: зазоры медь–медь с учётом классов обеих цепей, край платы,
  связность цепей (с учётом заливок своей цепи).
* **Обратная связь**: точки нарушений получают штраф в истории рёбер и перекладываются
  виновные связи; повторяющиеся места эскалируются вместе с соседями. Цепь, которую
  геометрия оставила разорванной, перекладывается целиком. Сохраняется лучший раунд.
* **Сглаживание**: короткий хвостик выхода поглощается, если трасса может зайти в
  площадку напрямую; выход из прямоугольной площадки — через середину грани под 90°;
  изломы скругляются касательными дугами с прогибом не больше 0,05 мм. Каждое
  изменение проверяется на зазоры.
* **Защита доводки**: этап, добавивший нарушения на слое, на этом слое откатывается;
  этап, разорвавший цепь, откатывается целиком.
* **Привязка к 45°** (`angle45`, выключена): готовые трассы приводятся к сетке
  0/45/90°, трассы с нарушениями возвращаются.

### 4.9. Выравнивание длин и сшивка полигонов
* **Длины**: меандры-тромбоны со скруглениями на прямых участках, амплитуда подбирается
  двоичным поиском так, чтобы не нарушить зазоры. Перекос дифпары считается по всему
  пути через промежуточные компоненты и компенсируется на более коротком проводнике.
* **Сшивка** (`stitch`, `route --stitch`): зоны перезаливаются через `kicad-cli`,
  строится граф островов (острова, соединённые площадками, трассами и переходными);
  каждая компонента связывается с главной переходным там, где острова двух слоёв
  перекрываются, или короткой дорожкой до заливки другого слоя. Площадки, до которых
  заливка не дошла (замкнутый термобарьер), получают короткую дорожку к заливке.

### 4.10. Запись
Отрезки и дуги записываются в `.kicad_pcb`; дуга у площадки или переходного
заканчивается отрезком 20 мкм (KiCad иначе не считает её подключённой), почти
прямые дуги пишутся отрезками, обрывки короче 20 мкм сливаются с соседним отрезком.

## 5. Параметры файла настроек

Все необязательны. Значения по умолчанию указаны в скобках.

| Ключ | Смысл |
|---|---|
| `order` | порядок разводки: `logic`, `width`, `cost`, `short`, `auto` (`logic`) |
| `short_link` | граница «короткой» связи, мм (3) |
| `terrain` | цена подъёма по контурной карте на мм дорожки; 0 — выкл. (1,5) |
| `terrain_sigma` | спад холма за полосой зазора, мм (0,5) |
| `terrain_via` | цена переходного на единицу высоты, мм (2) |
| `pad_exit` | выход из прямоугольных площадок под 90° (`true`) |
| `[via] cost` | цена переходного в мм дорожки (12) |
| `[via] diameter`, `drill` | размеры переходного (из класса Default) |
| `[[nets]] match, width, clearance, skip, priority` | правила цепей по маскам |
| `[layers."X"] role, direction, direction_weight, cost` | роль, направление и цена слоя |
| `[[diff_pairs]] p, n, width, gap, max_skew` | дифференциальные пары |
| `auto_diff_pairs` | искать пары по суффиксам (`true`) |
| `[[length_groups]] match, target, tolerance` | группы выравнивания длин |
| `length_reserve` | резерв под меандры: `auto`, `always`, `off` (`auto`) |
| `[centering] enabled, full, range` | выравнивание зазоров (вкл.; 2 и 5 каналов) |
| `trust_pours` | площадку, до которой дошла заливка, оставить заливке (`true`) |
| `pour_keepout` | зона у такой площадки, где сигналы платят больше, мм (0) |
| `keep_existing` | сохранить имеющиеся трассы (`false`) |
| `iterations` | итераций переговоров (40) |
| `mst_via_cost` | учитывать цену переходного в дереве связей (`true`) |
| `same_layer_bias` | множитель цены переходного для цепей, все площадки которых в одном слое (1) |
| `dynamic_terminals` | связь может закончиться на любой неподключённой части цепи (`false`) |
| `detour_relax` | ослабление направления слоя при чистке обходов (0) |
| `angle45`, `angle_cost` | привязка к 45° и цена отклонения от 45° (0) |
| `ridge`, `ridge_cost`, `center_gap`, `ridge_range`, `ridge_step` | эксперименты с полем расстояний до меди, выкл. |
| `force_fanout` | площадки `REF.PAD`, которым обязательно нужно переходное к плоскости |

Отладочные переменные окружения: `GRIDLESS_DEBUG_NET=имя` (как разведена цепь),
`GRIDLESS_TERRAIN_PNG=префикс` (картинка рельефа), `GRIDLESS_NO_VIA_RELAX` (не
сдвигать переходные), `GRIDLESS_DEBUG_DRC`, `GRIDLESS_DEBUG_POINT=x,y`.

## 7. Известные ограничения

* Цепи питания разводятся деревом из кратчайших звеньев между площадками, а не одной
  магистралью с отводами, как это делает конструктор.
* Внутри узла порядок связей не перебирается, а проводники узла не защищены от
  перекладки дальними связями: у NetK1_2 остаются 2 переходных, у эталона — ни одного.
* В плотной зоне (DA1/DA2) часть проводников ещё обходит чужие переходные петлями.
* Финальная резиновая нить изотропна: ортогональность и 45° не навязываются.
* RF-узлы и корпуса с шагом 0,4 мм требуют доработки шаблонов выхода.
