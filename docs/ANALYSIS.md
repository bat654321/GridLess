# GridLess: анализ аналогов и выбранные решения

Документ фиксирует, что было изучено перед разработкой, что из этого взято в GridLess и почему.
Состояние источников — на октябрь 2026 г.

## 1. Коммерческие трассировщики

| Продукт | Принцип | Что взято |
|---|---|---|
| **TopoR** (Eremex) | Триангуляция Делоне по выводам и препятствиям. Сначала строится только *топология* путей (с какой стороны какого препятствия идёт проводник), а точная геометрия и места переходных — позже, на «метрическом» этапе: любые углы и дуги. Последовательная укладка, перекладка (rip-up) со сложной функцией стоимости, «расслоение» — оптимизация распределения по слоям для минимума переходных. Архив вариантов, параллельные спуски. Нет предпочтительных направлений слоёв (изотропен). | Вся архитектура «сначала топология, потом геометрия»; геометрия с дугами вокруг площадок и концентрическими «пучками»; минимизация переходных отдельным проходом; автоматическое сужение трасс в узких местах; выбор эквивалентных выводов для дифпар. |
| **Altium Situs** | Топологическая карта платы задаёт путь, затем push-and-shove. Проход «Globally Optimised Main» сначала игнорирует конфликты, потом повышает их стоимость (переговоры). Направления слоёв задаются. | Переговорная перекладка с растущей стоимостью конфликтов; предпочтительные направления слоёв. |
| **Cadence Allegro PCB Router (SPECCTRA)** | Бессеточный, на основе форм; ранние проходы терпят конфликты, их цена растёт до полного запрета; затем очистка. Родоначальник формата DSN/SES. | Схема «конфликты разрешены, но дорожают». |
| **Siemens Xpedition Sketch Router** | Пользователь рисует эскиз пути шины — по сути задаёт гомотопический класс. | Идея на будущее: эскиз как топологическое ограничение. |
| **Zuken CR-8000** | Шаблоны топологии цепей (цепочка, звезда, H-дерево), учёт задержек. | Идея на будущее. |
| **Quilter, DeepPCB** | Обучение с подкреплением, облако, генерация множества вариантов. | Не используется: нет независимых данных о превосходстве над классическими методами на малых платах. |

## 2. Открытые решения

| Проект | Принцип | Что взято / почему нет |
|---|---|---|
| **Topola** (Rust, MIT) | CDT (spade) по «точкам», жгуты (bands) как цепочки изгибов вокруг «шестерёнок»; изгибы складываются концентрическими стопками. Поиск чередуется с рисованием геометрии; перебор порядков разводки при неудаче. Нет переговоров, дифпар, выравнивания длин. | Модель концентрических изгибов вокруг препятствий; тот же crate spade для CDT. Не взят перебор порядков (экспоненциален) — заменён переговорами. |
| **Freerouting** (Java, GPL) | Бессеточный: свободное пространство разбивается на выпуклые «комнаты», поиск по «дверям»; стоимости направлений по слоям, переходов, перекладки; затягивание (pull-tight), оптимизация переходных. Привязка к 45°. | Стоимость направлений слоёв (1.0 / 2.5 — порядок величин); «лучшая доска» сохраняется и восстанавливается; оценка результата. |
| **gEDA toporouter**, тезис **Tal Dayan** (1997), система **SURF** | Резиновая нить (rubber-band sketch) на CDT, регионы вокруг вершин, дуги + касательные. Раскладка по слоям секциями. | Основа модели: планарный эскиз на каждом слое, ёмкости рёбер. |
| **RBR** (S. Salewski) | CDT, состояние поиска (вершина, сторона), ёмкость рёбер «cut», штраф за сжатие. | Проверка ёмкости на рёбрах триангуляции. |
| **KiCad PNS** | Дифпары как две линии с «шлюзами» на концах; меандры (скругление, амплитуда, шаг), длина пары = max(P, N), отдельная компенсация перекоса. | Параметризация меандров «тромбон» со скруглениями; компенсация перекоса на короткой линии пары. |
| **OrthoRoute** (GPU) | Манхэттенская решётка + PathFinder на CUDA. Огромные платы, но качество «хорошее, не отличное». | Вывод: GPU не нужен для плат нашего класса (см. §4). Параметры PathFinder: ограниченный рост present-cost, история без затухания. |
| **tscircuit autorouter** | Грубая сетка ёмкостей + детальные решатели; пересечения стоят денег, а не запрещены. | Идея грубого этапа для плотных мест — на будущее. |

## 3. Что реализовано в GridLess

```
.kicad_pcb + .kicad_pro (+ <board>.gridless.toml)
   │  чтение: площадки всех форм, контур, зоны и запреты, медные полигоны,
   │  классы цепей, дифпары по суффиксам KiCad, плоскости (в т.ч. разделённые)
   ▼
Проблема: препятствия (скруглённые выпуклые многоугольники), места под переходные,
          соединения (MST, дифпары, переходные к плоскостям)
   ▼
Топология: CDT на каждый слой (spade). Провод = последовательность пересекаемых рёбер
          со строгим порядком на каждом ребре → эскиз планарен по построению.
          Поиск A* по состояниям «ребро + промежуток между проводами».
          Пересечь чужой провод можно только за цену перекладки (rip-up).
          Перегрузка рёбер разрешена со штрафом, растущим как в PathFinder; история
          конфликтов накапливается. Сужение ширины в узких местах.
          Минимизация переходных: каждое соединение с переходными пробуется без них.
   ▼
Геометрия: новая CDT только по реальным препятствиям; провода переносятся в неё.
          Переменные — положения пересечений на рёбрах; внутри треугольника провод
          прямой или огибает угол дугой, радиус которой учитывает вложенные провода
          (концентрические пучки, как в TopoR). Минимизация длины покоординатным
          спуском с ограничениями зазоров. Инициализация — алгоритм «воронки».
   ▼
DRC → обратная связь: штрафы в проблемных местах, перекладка затронутых цепей,
          лучший вариант сохраняется.
   ▼
Выравнивание длин (меандры-тромбоны), компенсация перекоса дифпар
   ▼
.kicad_pcb (отрезки, дуги, переходные) / JSON для плагинов KiCad
```

## 4. GPU

Рассмотрено по просьбе заказчика. Вывод: для плат 2–4 слоя и до ~300 цепей GPU не даёт выигрыша.

* Ядро — поиск A* по нерегулярной триангуляции (10³–10⁴ узлов на слой). Это очередь с
  приоритетами, ветвления и обращения по указателям; на GPU такие задачи упираются в
  накладные расходы запуска ядер и расхождение потоков.
* Вставка провода в топологический эскиз последовательна: каждый провод меняет эскиз
  для следующих.
* Вся задача помещается в кэш CPU; один поиск занимает доли миллисекунды. Полная
  топологическая разводка эталонной платы — 0,1–0,5 с, геометрия — несколько секунд.
* Где GPU реально помогает: волновое распространение по плотным регулярным сеткам
  (GAMER, InstantGR, OrthoRoute), DRC огромных плат. Это не наш класс задач.

Правильное применение параллелизма для нас — потоки CPU (rayon): одновременные прогоны с
разными порядками/весами и выбор лучшего (архив вариантов TopoR). Это следующий шаг.
